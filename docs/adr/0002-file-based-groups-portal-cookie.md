# File-based storage for the Groups Portal session cookie, not an env var

Every other piece of runtime configuration in this app (`LISTEN_ADDR`, `TRANSCRIPT_API_URL`) is an environment variable, read once at startup — simple, and consistent with itself. The Groups Portal session cookie broke that pattern by necessity: it's refreshed by hand roughly monthly (see [ADR-0001](0001-manual-session-cookie-refresh-for-church-guide.md)), and an env var can only be updated by restarting the process that reads it. That made every refresh a two-step "update the value, then restart the service" chore, and made [ticket 03](../../.scratch/church-guide-cookie-admin/issues/03-admin-page-and-nav.md)'s admin page impossible to build without giving that page a way to restart its own backend.

We moved the cookie into a small file (`internal/portalcookie`), read fresh on every Church Guide request instead of once at startup. This is the one configuration value in this app that isn't an env var — a deliberate inconsistency, not an oversight. In exchange, updating the cookie (by script today, by an admin page in ticket 03) takes effect immediately, with no restart and no coordination with the process's lifecycle.
